## 4. Build Reproducibility Gaps & Pinning Recommendations

To achieve bit-for-bit deterministic reproducibility:
1. **Pin Multi-Stage Base Images by Digest:**
   ```dockerfile
   FROM composer:2.7@sha256:56b0b5711e956973e3e2cf61a38a7cbbbe72bbd9fe2cf87be58cbb22a8ec5ff0 AS vendor
   FROM node:20-alpine@sha256:d8c5bc8b1e8d98d022b7a0d4c79590d9b626e5e8e3d23192244a1ae98980313f AS assets
   FROM php:8.3.36-fpm-alpine@sha256:4bba7da77c6a8473122b7826df62763b5639d89b1eedfe6d38ffa10bb222f4fa AS builder
   FROM php:8.3.36-fpm-alpine@sha256:4bba7da77c6a8473122b7826df62763b5639d89b1eedfe6d38ffa10bb222f4fa
   ```
2. **Pin Alpine Package Versions:**
   Prevent upstream Alpine repository updates from breaking build extensions by pinning `apk add` versions or maintaining a local package mirror.
3. **Immutable Container Replacement:**
   Rebuild `app-1` and `app-2` using `docker compose build --no-cache app-1 app-2` to bake updated `composer.lock` and eliminate writable-layer drift.
